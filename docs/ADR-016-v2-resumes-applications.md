# ADR 016 简历事实与版本绑定申请

日期：2026-10-21。范围：V2 CP-200/201/210/211 的本地文本与站内渠道。

简历和申请复用 0003/0004 私有聚合，不增加迁移。`resume_fact` 保存本人确认的陈述、原材料引用及记忆/档案版本；`resume_fact_revocation` 追加撤销记录。确认不代表独立核实或技能验证。文本简历通过受控导入、按行预览、栏目校正和逐项确认形成事实；支持 UTF-8 txt/md/json、1MiB、100 条候选，超出条数明确提示拆分。不解析上传的 PDF/Word 原件。

`resume` 是含标题和当前版本指针的可变根，使用 If-Match；`resume_version` 是只追加的内容快照，包含事实、岗位原文哈希/要求/来源和序号。根版本 2 指向第 1 个内容版本，后续根版本和内容序号分别递增。编辑、按 JD 排序和恢复都创建新内容版本；恢复保留原岗位快照。定制只在同类陈述内按已有关键词排序，不添加业绩、年限、熟练程度或 JD 技能。ATS 检查使用冻结岗位要求，缺词只提示；检查姓名、联系方式、来源有效性和过长段落，不承诺外部 ATS 的结果。

来源删除、改版、推断/替代或撤销会阻止新版本、导出、材料草稿及申请准备继续使用，要求另行确认事实。历史快照保留用于核对旧申请；账号注销删除全部私有聚合。记忆修改/删除/偏好解决、档案保存/恢复和导出都使用同一用户锁，避免 PostgreSQL 下检查后来源变化。不可变记录依然按用户/租户隔离。

Word 和 PDF 使用同一逻辑段落列表。Word 由受控 OOXML ZIP 生成，固定 A4、正文和标题样式，无宏或外部关系；PDF 使用已锁定的 Playwright/Chromium，禁止脚本和所有网络请求，正文转义。Playwright 从开发依赖移为运行依赖，锁文件版本不变；Compose 镜像已有浏览器与中文字体。文件名包含简历根短号、版本和岗位短号，响应带内容与字节哈希，禁止缓存。部署环境需提供锁定的浏览器及中文字体。LibreOffice/Poppler 仅用于隔离的导出 QA 镜像，不进入应用镜像或宿主安装。

`job_application` 创建时绑定不可变简历版本、标题、序号及哈希，同时保存岗位快照。一个岗位仅允许一个进行中申请；更新需 CAS，旧版本不被新简历改写。准备阶段要求五项明确检查（事实、联系方式、要求、隐私、源站人工核对）、有效来源、姓名/联系方式与当前岗位版本。关闭、疑似过期、截止已过或岗位变化会拒绝准备。当前不提供自动投递或邮件发送。

通用状态更新不能将申请改为 submitted。本人无凭据报告提交时，状态仍为 awaiting_user_submission，verification 为 pending_verification。本人确认文本材料、材料版本、提交时间、编号和绑定岗位/简历后，才按保守成功/失败关键词、岗位/企业上下文和编号规则核对；通过则为 `user_confirmed_receipt`，明确不是源站独立验证。该机制不能证明用户上传文本本身的真实性，不把上传材料或模型陈述冒充 provider 回执。

`application_reminder` 是明确授权的一次性站内提醒，覆盖截止/笔试/面试/跟进，支持配置、暂停、恢复和取消。IANA 时区处理 DST：不存在的时刻拒绝，重复时刻取首次；静默后截止提醒不得越过截止日。Worker 对每个提醒在短事务中获取用户锁、重新检查配置，原子保存稳定 ID 通知与 delivered 状态。此过程没有外部副作用，不需要长任务租约；失败回滚后可重新消费，重复调度不会重复通知。结束的申请停止提醒。通知保留来源、当前岗位状态及变更提示；离线恢复后的到期通知要求用户重新核对，不声称仍可投递。通用多步骤恢复仍属于 CP-221 后续范围。

验证包括合同、真实 Chromium 下载和独立 Worker、SQLite 快照恢复、PostgreSQL、账号导出/注销及两种导出格式的全部页面。证据与实际结果见 历史验证摘要（产物已清理）。
