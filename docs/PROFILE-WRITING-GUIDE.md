# 个人资料与求职材料填写指南

更新：2026-10-27。用途：帮助本人整理可复用的真实资料，也作为后续 React 网页资料表单的字段设计输入。网页与 Docker 重构范围见 [重构规范](WEB-REFACTOR-PLAN.md)；W-056 已提供分步档案、私人草稿、按行校正和结构化经历；细节见 [实现契约](WEB-CONTRACTS.md)。所有方括号都是待填写提示，不是事实，不应直接当作正式简历内容。

当前应用支持 UTF-8 txt/md/json 材料（不超过 1 MiB），按行提取后本人逐项确认；不支持 Word/PDF 原件直接解析。本指南的 Markdown 可在本地填写后导入；目前不会自动把以下所有字段转换成结构化档案，也不会自动完成跨页预填。统一资料流程设计见 [功能收敛设计](PRODUCT-FOCUS.md)。

## 1. 填写顺序与信息边界

先填目标岗位、已有教育/经历和每周可投入时间，再整理项目与成果来源，最后选择事实生成求职材料。想先探索方向时允许目标未知，不需先把全部资料填满。

只写本人能解释的事实。没有明确结果可以留空；计划完成、本人陈述、客观测验通过分别记录。团队整体成果要说明个人负责部分，不把团队人数、收益或获奖当作个人贡献。

联系方式只在实际求职材料需要时填写。身份证、银行卡、账户密码、访问令牌和模型密钥不放入材料；公开仓库或演示链接先检查是否含私人数据。导入个人材料不等于同意上传给外部模型或公开分享。

## 2. 可复制的资料结构

以下各块可按需使用，不要求一次填完。当前应用的正式档案仍需要完整字段；日期、预算等未确定时先保存私人档案草稿，不能为通过表单填写虚构值。

### 基础档案与约束

```text
# 基础资料
称呼：[希望如何被称呼]
学历：[专科/本科/硕士/博士/其他]
学校：[真实名称；暂不需要可留空]
专业：[真实名称]
年级：[目前阶段]
预计毕业：[已知日期/仅知年月/尚未确定]
时区：[例如 Asia/Shanghai，按本人情况填写]

# 目标与安排
当前阶段：[探索方向/准备实习/校招/其他]
主目标：[岗位方向；未确定可写待探索]
备选目标：[选填]
目标时间：[已知时间或待确定]
期望城市：[逐项填写；是否接受异地/远程另写]
每周可投入：[小时与分钟；0 表示暂不安排，未知请写待确定]
可实习时间：[起止/每周天数/连续月数，按已知内容填写]
期望薪资：[金额、税前税后、月薪年薪；未知留空]
资格或其他硬限制：[选填，只写与岗位相关内容]
偏好与不可接受条件：[选填]
```

当前档案的毕业日期要求完整日期，城市为必填，周预算内部使用分钟；这些限制尚未因本文改变。已有材料只知道毕业月份时应保留原文，等待补全或新表单的日期精度支持，不自行编造日期。

### 教育经历（每段一份）

```text
# 教育背景
学校与学历：[真实名称及阶段]
专业/研究方向：[真实名称]
起止时间：[已知精度]
与目标岗位相关的课程/研究：[只列确有经历的内容]
论文/竞赛/证书：[名称、时间、本人角色；选填]
可核对来源：[证书、课程记录、论文链接等；可只记本地位置]
尚待确认：[不确定的名称、成绩或时间]
```

### 实习、工作或其他实践（每段一份）

```text
# 实践经历
单位/组织：[真实名称；敏感信息可在私人资料中标注]
职位/角色：[本人实际身份]
起止时间与投入：[已知日期精度、全职或兼职]
背景与任务：[为什么要做、需要解决什么问题]
个人行动：[具体做了什么、用了什么方法、负责哪个部分]
结果：[可核对的产出；没有测量就写具体完成内容]
量化依据：[指标定义、比较条件、时间与来源；没有则留空]
团队与个人边界：[哪些由本人完成，哪些由他人完成]
来源：[文档、提交、工作记录；无权限公开的仅保留私人引用]
待核实：[尚不能确认的内容]
```

### 项目与成果（每个项目一份）

```text
# 项目经历
项目名称：[真实名称]
项目类型：[课程/个人/研究/团队/实习等]
起止时间：[已知精度]
目标岗位/技能：[与项目实际相关的岗位和技能]
背景 Situation：[实际问题与使用场景]
任务 Task：[本人承担的任务]
行动 Action：[设计、实现、调试或协作中的具体个人行动]
结果 Result：[交付物或已测得结果；未知留空]
个人贡献边界：[负责范围，不能确认的比例留空]
技术与选择原因：[真实使用过的技术及取舍]
验收方式：[测试、演示或人工检查的范围与结论]
成果来源：[commit/PR、文档、演示或本人保存的业务成果]
局限与下一步：[尚未实现或验证的内容]
当前状态：[草稿/本人已核对；客观评测结果另记]
```

当前练习项目转简历事实须符合现有项目来源和有效代码回执规则；其他真实经历可走本人确认的经历事实流程，仍不能因此宣称技能已客观验证。GitHub 链接本身不证明代码通过或贡献归属。

项目的真实业务成果与来源按业务规则保留。开发测试的截图、录屏、日志、测试报告和校验样本只在系统临时上下文中查看，用完清理，不为整理资料创建持久验收证据包。

### 技能陈述

```text
# 技能与证据
技能名称：[具体到能描述任务的技能]
能完成的事情：[真实任务，避免只写“精通”]
最近使用：[时间与场景]
来源：[项目/课程/实践/客观测验，关联前面条目]
证据范围：[哪些行为已检查，哪些尚未检查]
待补足：[仍不熟悉的部分]
```

自评和导入材料属于能力线索。只有符合系统规则的有效考核/项目回执才参与对应范围的已验证能力更新。

### 岗位/JD 材料

```text
# 目标岗位
岗位与企业：[原文名称]
原始链接：[可选，不编造链接]
获取日期：[实际日期]
岗位正文：[保留职责、必需条件、加分项、地点、届别与截止等原文]
本人关心的问题：[希望比较或待向招聘方核实的内容]
```

岗位要求以原文为准；缺失的薪资、截止、实习月数等保持未知。粘贴岗位时避免混入本人评价，以便核对提取依据。

## 3. 从资料生成求职材料

选择具体 JD，再选有关教育、经历、项目和技能事实。简历先写“做了什么、个人负责什么、有什么可核对产出”，已有量化依据再写指标。

可使用的句式是：`在[真实场景]，负责[个人任务]，采用[实际方法]完成[交付物]；[有依据时填写结果与测量条件]。`

面试准备复用同一项目条目，补充选择原因、困难、取舍与反思，不另写一套相互矛盾的经历。自我介绍和求职信只调整组织与表达，不能生成新的学历、任职、业绩、证书或贡献。

已确认事实有变化时修订来源并生成新材料版本；已投递申请继续关联当时版本。来源撤回/失效后，旧快照仅供历史追溯，新的导出或使用按有效性规则处理。

当前统一在“我的资料”维护基础档案、材料、结构化经历、项目成果及求职事实；“求职”选择同一事实生成简历和面试上下文。分步填写可先保存私人草稿；事实来源发生变化时仍须重新核对，不自动修改历史输出。

## 4. 导入前与日常维护

删除模板中未填写的提示；保留真实未知项及原因。建议按主题拆成基础资料、教育/经历、各项目和目标 JD；当前单次最多预览 100 条非空行，较长内容分开导入。同一材料不要在不同页面重复上传，先查看已有记录。

模型生成的是草稿，逐项对照原文确认姓名、日期、角色、数字、技能和来源。重复或冲突信息先核对来源，不选择“更好看”的版本。没有结果可以清楚说明产出与局限。

私人资料存放在本人受控目录，避免提交到项目仓库。资料更新时优先修改来源，再检查计划、事实、简历和申请的受影响状态；业务备份与资料本身按既有保留规则管理。
