# ADR-015：岗位发现、反馈与本地库增量订阅

日期：2026-10-21（Asia/Shanghai）。用户沿已有 V2 授权要求继续推进。

## 范围与存储

CP-133 的本地岗位库闭环，以及 CP-191 的模式与反馈功能。本批不引入外部招聘搜索源或邮件服务。CP-191 可消费 CP-190 已有的“未知项目分项”契约，但在 CP-190 完整退出前不把 CP-191 整体标为已验收。CP-221/240 仅积累调度/站内摘要子项，其他恢复工作流、邮件、周报和漏斗仍待开发。

继续使用 0003 的私有聚合及追加历史，不改表或引入依赖：

- `job_preferences`：收藏、企业精确名称屏蔽、关键词排除、启用模式；确认及 CAS。
- `job_feedback`：每人每岗位一个稳定 UUID 记录，标签/原因/生效状态可更新、撤销、追溯历史；所有引用先核对岗位所有权。
- `job_subscription`：筛选、频率、时区、静默、配置代次、下次执行、待处理任务、已见指纹。
- `subscription_run`：与 BackgroundTask 同 ID，保存订阅/配置代次、结果及来源范围；API 同时展示真实任务状态、尝试和错误类别。
- `job_digest`：追加站内变化摘要，关联订阅、任务、岗位版本、字段/来源、检查时区；已读状态 CAS。

新私有记录沿用账号导出/注销；恢复演练新增偏好、反馈、解释快照、订阅指纹与待执行任务，恢复后不会重复通知已见内容。

## 过滤、比较与推荐

搜索、交互匹配及订阅使用同一企业/关键词规则。收藏不删除被屏蔽或关闭的原文，明确选择的历史岗位仍可比较/查看。匹配返回额外 hidden 组，屏蔽不改写硬条件结论，也不保留“可进入高匹配”的标志。

2—4 岗位对比必须全部属于当前用户；未知字段保留未知和原文版本。原始解释分不被反馈改写，组内另算推荐排序分。喜欢 +5、不感兴趣 -20、误判 -10；已投递仅自记并退出推荐，不能写申请状态或伪造回执。FAIL/hidden 永远不进入模式候选，UNKNOWN 单列待核实。

模式规则 `recommendation.v1`：最匹配按分项/反馈；可冲刺为 1—2 项基础必需技能待验证；入门为识别到 1—2 项必需技能；探索提供方向对比。当前不推断潜在兴趣或保证就业，模式均可关闭，反馈可撤销。

## 调度、静默与提交一致性

Worker 每轮在既有任务消费前发现到期订阅；锁定用户后重新读取订阅状态，使用配置代次/计划时点的幂等键入队 `market.subscription`，同一订阅只允许一个排队/运行任务。HTTP 公共基础任务接口仍限定原白名单，不能绕过订阅确认直接入队。

日/周计划按 IANA 时区的本地小时计算，非整小时时区保留本地整点。DST 不存在的小时跳过、重复小时仅首次；静默开始等于结束表示关闭静默。进入静默时顺延，不通过长时间睡眠占用 Worker，也不把静默顺延计为失败尝试。延迟启动的 Worker 再次核对静默。

配置/暂停/取消在同一事务取消旧排队或运行任务并递增配置代次。恢复显式进行；更改筛选范围或“仅收藏”建立新基线，普通时间/名称编辑保留指纹。

处理事务先锁定用户，再原子核验任务状态、租约 token 和到期时间。原文扫描、指纹、摘要与 run success 原子提交；提交前再核验租约。陈旧租约不能写入，失败整体回滚。提交后、runtime 确认前崩溃时重放读取已提交 run success，复用既有重试/退避/死信，不产生第二份摘要。

## 增量口径与边界

只扫描本人已导入的库，不访问来源 URL。首次匹配建立基线；后续按规范空白后的原文及有效状态计算指纹。新增来源链接、核对原因、收藏/屏蔽撤销均不被当作岗位实质变化。已见岗位出现新内容、关闭、合并、疑似失效、明确截止或不再满足筛选时记录一次变化。屏蔽的岗位不推送；没有变化不产生通知。

明确截止日期到期可被检测，源站是否实际关闭需要用户更新或后续获准适配器，不能把本地扫描称作实时失效核验。当前不宣称大库容量、邮件投递、生产 RPO/RTO 或完整 V2 出口。

回滚无数据库降级：停止新 Worker，恢复旧入口/静态脚本及受控任务白名单。保留新聚合，避免删除开发卷或历史摘要；旧 Worker 不应继续领取本批新任务。
