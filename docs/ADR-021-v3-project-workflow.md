# ADR-021：项目阶段、成果、计划预览与确认陈述

日期：2026-10-21。状态：V3 第二批实现。验证见 历史验证摘要（产物已清理）。

## 决定

1. 实践项目保留模板及岗位版本。设计、复盘阶段可记录 pending/in_progress/completed、实际过程与关联成果；完成是本人陈述，不产生技能证据。实现阶段状态派生自当前有效、对应最新提交的受信代码回执，不能通过手工打卡设为通过。旧的字符串阶段状态在读取时兼容，不修改历史版本。
2. 私人成果支持 64 KiB 内的 UTF-8 txt/md/json 文本，以及用户主动提供的 GitHub commit/PR 引用。文件名不允许路径；文本沿用控制字符、明显凭据及 EICAR 扫描。GitHub 引用必须为 HTTPS、固定主机和 commit/PR 路径，禁止凭据、查询参数和片段；不发起请求，不证明账户绑定、仓库归属或代码质量。上传、下载、撤回和历史均遵循本人所有权。撤回保留历史，不冒充物理删除；账号删除清理全部私人聚合。
3. 项目可生成学习计划预览：保留已有任务和已跳过记录，保护完成/锁定及其先修闭包，补齐当前词库先修，将里程碑拆为最多 90 分钟且不超过本人周预算的任务。依据本人时区安排未来日期，核验总周预算、DAG、先修与截止日。用户接受才原子改计划；拒绝不改计划；并发接受仅一个生效。已有项目任务不重复添加。
4. 预览绑定原计划版本、档案/目标/词库/证据上下文，以及项目、制品、回执、成果和陈述版本。来源变更使待接受预览失效。已接受任务保留其当时项目版本；后续修改不会静默抹去已投入工作。项目打卡不写 foundation 证据；基础技能通过测验后，重排也不会因此删除未完成项目任务。完整任务跨目标切换仍遵循原预览及保护规则。
5. STAR 的背景、任务、本人行动、结果由用户填写并保留版本。确认须有实际背景、任务与行动，结果/贡献/业务指标可以未知。草稿只复制用户已填内容，遗漏项列为待确认；有有效回执时另列有限代码测试结论。确认陈述且代码通过后，用户可再确认将当前版本保存为不可变简历事实，来源绑定陈述、代码、回执版本和关联成果。不自动补充数字或升级能力。
6. 陈述改版产生 needs_reconfirmation，撤回/成果失效产生 source_withdrawn；旧简历文本保留历史但不能用于新材料/申请。旧基础成果陈述保持兼容。V2 面试只关联当前事实版本的项目回执，材料来源失效后拒绝继续相应会话；面试评价不写能力台账。原评价仍是当时冻结结果。
7. 阶段复核保存不可变清单、rubric、来源快照、本人结论和局限。接受要求设计/复盘阶段完成且当前测试通过；用户可记录仍需修改，但不能人工覆盖测试失败。复核不另写技能证据，不扩大有限测试范围。最新复核才可显示为当前，来源变更、代码撤回、过期或证据变化使旧复核成为历史。

## 验证和边界

复用 GrowthRecord/Revision、所有权锁与 CAS，无新增迁移、依赖或外部访问。共享 PostgreSQL/备份恢复合同用独立合成账号，明确模拟评测回执；真实宿主 Docker/Chromium 演练另外验证实际生产链。二者不得混称。

当前只有一个 Python 数据处理模板，文件为纯文本，不支持任意工程、图片/视频解析、私有仓库、GitHub OAuth 或生产专用沙箱。CP-113/143/154 仍待后续。此批不会将主动提供 GitHub 链接记作 CP-113 账户绑定完成。
