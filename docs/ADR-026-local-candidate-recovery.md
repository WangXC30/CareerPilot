## 发布候选

`infra/Dockerfile.candidate` 从现有固定依赖工具镜像打包当前源码，运行时按镜像 ID 固定，使用非 root 用户；不挂载宿主源码或真实业务数据。该镜像仍继承开发工具链及其镜像层，不能替代最小化运行镜像、漏洞评审、签名和供应链治理。

独立 `infra/compose.candidate.yaml` 不与默认 Compose 合并。应用只读文件系统、丢弃 capabilities、禁止提权，仅 `/tmp` 可写；两份 API、两份 Worker 共享独立 PostgreSQL，启动前由单次迁移作业升级和播种。应用角色非超级用户，无建库/建角色权限，但拥有应用数据库和 schema 以支持迁移；正式生产应进一步分离迁移和运行角色。

文件密钥通过 `CAREERPILOT_DATABASE_URL_FILE` 读取；candidate 模式拒绝明文环境 URL、缺失文件及非 PostgreSQL 配置。开发模式仍兼容原有 SQLite 配置，同时设置两种来源会失败。文件读取设长度上限，错误不回显内容和路径。Compose 文件密钥是本地注入机制，不等同于生产密钥托管或轮换服务。

HAProxy 根据 `/health/ready` 排除不可用 API，不重试 HTTP 请求，避免重复写入；数据库、业务 API 和 Worker 只接内部网络，入口额外连接独立 edge 网络，端口仅发布到 `127.0.0.1`。恢复专用 API 也连接 edge 网络；不提供公网 TLS、负载均衡控制平面或访问授权。单机 Docker、单个数据库和单个入口仍是故障域，双 API 不构成跨主机高可用。

## 故障与事务边界

SQLAlchemy 连接池 checkout 时检查存活连接，PostgreSQL 建连超时 3 秒；candidate 模式另限定池等待、连接数量和 SQL statement 超时。存活探测只替换失效连接，不能恢复已中断的事务；调用者仍需依据业务幂等键和版本处理结果未知的写入，参见 [SQLAlchemy 断线处理](https://docs.sqlalchemy.org/en/20/core/pooling.html#disconnect-handling-pessimistic)。

Worker 遇数据库连接类错误时删除心跳，以固定错误码记录并等待下一轮；一次模式返回非零，其他未预期错误退出并交由容器重启策略处理。未记录 SQL、参数或异常正文。下一轮仍走已有事务、租约、CAS 和 outbox/inbox，不直接重放外部动作。健康检查暴露故障状态，本地脚本实际观测恢复；没有接入生产告警通知、值班响应或月度可用性监测。

## 可重复运行与清理

在项目根目录运行：

```powershell
python -B scripts/candidate_drill.py
```

需要 Docker Compose 和已有 `careerpilot-dev:local` 镜像。首次可能拉取 PostgreSQL/HAProxy 镜像；不读取项目 `.env`，不传递模型凭据，不调用付费模型。脚本构建候选镜像，在系统 `TemporaryDirectory` 生成随机数据库密钥、空 env 文件、灰度覆盖文件和备份，创建带随机命名空间的独立容器、网络和数据库卷。创建资源前检查配置的端口、网络、卷、身份和权限约束。

演练创建两名合成用户及目标、档案、岗位、计划、后台任务，测试并发身份隔离、重复写入、节点退出、失败配置灰度及回滚、数据库停机健康信号和原进程恢复。备份使用 `pg_dump -Fc`，通过 stdin 在另一个空 PostgreSQL 实例执行 `pg_restore --exit-on-error`，再用恢复 API 核对会话、所有权及幂等结果。只恢复本次可信合成库，机制见 [pg_dump](https://www.postgresql.org/docs/17/app-pgdump.html) 和 [pg_restore](https://www.postgresql.org/docs/17/app-pgrestore.html)。

校验通过后将完整配置冻结到同一临时目录，启动和清理始终采用这份资源名称；源文件中途变化不能重定向清理，校验未通过时不执行删卷。成功或失败均在 `finally` 对本次随机项目执行 `down --volumes --remove-orphans`，确认容器、卷、网络已清空，然后移除系统临时目录；不输出原始日志、凭据或导出样本。候选镜像作为工程构建缓存可保留，镜像不包含本轮测试数据、密钥、备份或报告。强制杀进程/宿主机断电可能绕过 finally，恢复工作时应先核实本次项目标签和绝对临时路径，再清理对应遗留资源，不操作默认业务项目。

## 保留的正式门槛

本地演练仅给出合成工作负载、单机故障和快照边界的观测。配置灰度回滚没有验证跨版本二进制兼容或数据库迁移回退；并发身份读取不替代职位搜索、完整页面、长期负载或峰值容量测量；快照恢复不证明生产 RPO/RTO。

正式环境仍需实际托管与故障域设计、TLS、专用密钥托管及轮换、对象存储租户隔离、异地加密备份与 PITR、告警及值班、镜像审计签名、真实发布灰度/兼容性、容量及月度可用性评审和 RPO/RTO 决议。现有材料/音频业务的数据库所有权与删除规则继续适用，本轮没有新增或验证真实对象存储。CP-262 法律签核及协作 No-Go 保持原决定。

2026-10-26 演练等待修正：轮询入口的一次成功可能只命中仍存活的 API，不能证明失败副本已经退出路由。节点停止后改为六次连续身份读取成功才报告稳定，失败响应或连接错误重置连续计数；随后仍严格验证 20 次读取及快照。输出时间包含稳定性确认窗口，不与旧单次健康响应耗时直接比较，也不充当正式 RTO。
