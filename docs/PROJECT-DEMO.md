# 核心演示与验证说明

## 演示准备

演示使用隔离的临时数据库和合成资料，不使用真实个人资料。下面的自动化演示会自行创建并清理临时数据库；README 中的普通启动使用持久业务卷，适合实际使用。真实模型检查使用独立合成输入和现有工作区额度，不写入模拟业务资料。

自动化隔离演示可执行 `docker compose run --rm --no-deps checks python scripts/browser_web.py --journey-only`。该脚本使用临时数据库及模拟模型，结束后清理；它验证的范围和真实模型体验不同。README 的普通启动命令使用持久业务卷，不应向现有业务库写入演示数据。

需要复测真实模型时，可在已更新的 Worker 中运行 `docker compose exec -T worker python scripts/evaluate_chat_live.py --allow-external`；用 `--case greeting` 可只运行一条样本。还可单独选择 `job_injection`、`ambiguous_resume` 和 `external_send`，检查岗位原文含指令、简历资料不足与外部发送请求时的首步决策；这些扩展样本不进入默认三条调用。脚本不执行工具、不读取个人资料、不生成报告；通过现有工作区授权与配额记账，会产生费用。默认不输出模型正文；需要本人语义复核时，可在交互终端运行 `docker compose exec worker python scripts/evaluate_chat_live.py --allow-external --case external_send --human-review`，临时查看回答并输入结果，完成后关闭终端，不要重定向到文件。该复核只代表一次合成样本，不能证明后续工具链或整体模型准确率。

## 核心流程

1. 导入一份合成岗位描述，包含明确的技能要求；确认解析结果，缺失条件保持未知。
2. 填写合成个人资料和每周学习时间，选择岗位后查看能力差距及依据。
3. 请求生成学习计划，核对任务、时间预算和先修依赖；先保存草稿，再明确确认发布。
4. 记录一次学习或项目成果。区分本人自述、本人确认与可客观验证的证据，不因完成任务自动宣称技能已验证。
5. 选择有效事实生成简历草稿，核对来源和版本后保存；申请记录仅表示本地状态，不自动投递。

## 重点说明

- 对话写操作先预览并确认；确认后重新校验版本和上下文，成功、拒绝与失败使用不同回执。
- 相同请求的防重依赖幂等键和业务回执；不要将其概括为跨所有系统的 exactly-once 保证。
- 来源修改后，新操作需要检查来源有效性；已保存的历史快照不应被静默改写。
- Docker 停止后 Worker 不再执行；本机数据备份和恢复需按现有流程处理。

## 验证方法和边界

自动化回归覆盖范围及历史结果见 PLAN；一次真实演示应单独记录是否使用真实模型、执行日期、所用版本与实际失败情况。可使用清晰意图、信息缺失、冲突资料、拒绝确认、重复请求和过期版本等合成场景检查工具选择、参数、确认与恢复；不要把模拟调用或样本通过率解释为真实用户效果。

前端请求边界可通过 `docker compose run --rm --no-deps checks python scripts/browser_web.py --asset-loading-only` 复验。该检查在临时数据库建立三份合成简历，核对助手首屏未加载延迟页面资源、版本选项只发起一次批量请求，以及进入学习和求职时加载相应页面；它不测真实设备加载时间。

测试截图、录屏、日志、报告、验收清单和导出校验样本只在系统临时目录中生成，成功和失败均清理。真实模型输出未经核验前不作为效果结论。个人贡献、性能提升及可靠性数字必须由实际工作和测量支持。

## 项目介绍与技术讨论

可以用以下方式介绍项目，再根据本人实际贡献调整：

> CareerPilot 是单人本地求职准备工作台。用户导入目标岗位，结合已有能力证据制定学习计划，并将经确认的成果用于简历。助手负责理解意图和生成建议，计划约束、来源检查和业务写入由领域服务控制。

技术讨论可以围绕两个具体场景展开：

1. **确认与恢复**：展示待确认操作的预览，解释确认后复核版本、写入与回执的事务边界，以及请求重试时如何避免重复写入。失败后的状态以实际回执为准，不泛化为所有外部系统的 exactly-once 保证。
2. **事实与快照**：解释个人自述、确认事实、客观测验之间的差别；演示修改来源后新操作如何复核有效性，历史简历和申请如何保留当时的快照。

还应能说明为什么当前选用 SQLite 与单机 Worker、哪些条件下需要重新考虑并发和访问控制，以及外部模型授权、失败和费用如何处理。不要把离线规则结果、模拟模型结果或参数化题量写成真实模型准确率或独立知识点数量；简历中的职责和量化收益须由本人经历及实际测量支持。
