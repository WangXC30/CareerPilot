# ADR-014：V2 首批职业比较与三值匹配

日期：2026-10-21（Asia/Shanghai）。状态：已实现，首批本地验证见 当前测试脚本（产物用完删除）。

用户已确认 V0/V1 验收并授权 V2。首批从 CP-121 和 CP-190 的确定性核心切入，沿用 FastAPI、现有静态工作台与 Compose；不重建前端、不改参考项目，也不引入未配置模型或外部来源。

## 决策

- 匹配先计算学历、届别、地点、实习时长、工作许可/资格和有效性，每项为 PASS/FAIL/UNKNOWN；任一 FAIL 排除，任一 UNKNOWN 留待核实。只有全部 PASS 进入明确符合组。每项保留原文跨度与用户条件。
- 规则保守识别单一最低学历、单一届别、已收录精确城市/用户已填城市（允许“市”后缀）、简单最低月数与精确资格名称。区域、并列/附加限制不由规则猜测。用户档案缺失不补齐；未列明许可/资格不假设无限制。城市默认作为硬约束，用户可明确解除。
- 软评分使用实验权重 35/25/20/10/10；未知部分得分为零、单独列出未知与已知权重，不重分配权重。城市与明确元/月薪资各占偏好的一半。基础测验只计入对应基础技能；相同技能重复提及不重复计算。项目验收缺位时项目分项保持未知，不将材料、课程或 README 变为已验证项目。分数不是招聘录用概率。
- 每次 GET 读取当前档案、条件、证据有效期/撤销与最新能力状态，避免旧缓存继续推荐过期或不符合岗位。截止与新鲜度按档案时区日期计算；新鲜度只用原始发布日期，未来/无效日期未知。
- `matching_constraints` 与 `match_snapshot` 使用现有私有聚合及版本表，无新增数据库表或迁移。条件更新须确认及 If-Match，锁定用户再检查版本；解释快照只创建/读取，不能编辑。快照保留档案、条件、岗位、目标、规则、权重及技能证据引用。导出/注销覆盖所有新私有记录，SQLite/PG 共用领域路径。
- 职业比较按明确兴趣→主目标→基础补课分钟排序。先修依赖计入成本；已通过且有效的基础技能显示可迁移性，估计周数仅是基础学习预算下界。专业和自由文本偏好原样展示，尚未建立适配模型时不编造专业资格关系。
- 岗位样本仅统计本人导入且未关闭/合并/疑似失效/过期的 JD，按“要求或优先技能中至少半数属于路径”归类；显示分子、分母、来源和版本，样本允许多路径重叠，不代表市场供需/薪资趋势。

## 边界与后续

CP-121 以当前软件基础目录和可追溯的小样本口径验证。CP-190 核心可供使用，但项目证据接入尚未完成，该任务维持开发中。剩余 V2 任务及 CP-303/304/306 不计本批完成；无外部投递或邮件发送。

复杂城市/学历/实习约束可通过原文核实并修订档案或导入新 JD；当前宁可 UNKNOWN，也不将歧义解释成满足。将来扩展规则须升级版本及固定日期金标，仍保留旧解释。

回滚：新增功能无迁移；恢复旧版 `api.py` / 页面脚本及检查入口即可关闭新功能。已存私有记录继续保留，不删除开发卷或回写历史快照。不要运行旧阶段源码哈希门禁作为新阶段发布条件。
