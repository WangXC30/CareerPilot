# ADR-001：V0 首批独立底座与复用边界

- 日期：2026-10-19（Asia/Shanghai）
- 状态：本地工程试行；第三方整体复用 Go/No-Go 待 Spike，不是 V0 出口批准
- 决策记录者：Codex；依据用户“按照项目已有文档，开始初步阶段开发”授权
- 对应：CP-002/003/004/005/006，ARCHITECTURE ADR-001/002/003

## 背景与选择

主工程此前仅有四份文档。MyCareer 包含单 worker 防护、API Key 身份和多个 SQLite 存储，直接整体继承会使 CareerPilot 的领域与迁移受到现有结构约束。三个参考项目的根许可证为 MIT，依赖及素材审计尚未完成。

选择新建 Python/FastAPI 模块化单体，用 SQLAlchemy/Alembic 与本地 SQLite 验证最小持久化与身份切片。纯领域契约不引用参考项目；后续复用必须经适配器及所有权合同测试。当前没有复制第三方业务源码或安装其完整运行时。

备选是直接扩展 MyCareer 整体应用；在对象授权、共享存储、任务恢复、依赖许可证与部署复现有充分证据前，不接入主工程。另一备选是立即上 PostgreSQL 与前端全栈；本批先验证本地 API 与约束，保留后续真实数据库合同测试入口。

## 试行边界与取舍

- 个人本地开发，监听 loopback；限时随机令牌由 CLI 发放，服务端摘要查验，身份不来自客户端 user_id。
- 目标草稿用于隔离、版本与幂等验证；不代表 CP-122 业务验收。
- 创建目标、幂等记录与审计同事务；并发重放冲突可以返回 409，客户端以原键重试；不宣称 exactly-once 或已实现 Outbox。
- 单主目标由条件唯一索引约束；业务激活和状态迁移以后实现。
- 不接入外部模型/采集/高风险工具，预算和授权机制仍待后续任务。
- SQLite 单机、正式认证、PostgreSQL、Worker、UI 均有明确后续任务，不能外推到生产可用。

## 验证和回滚触发

证据见 当前测试脚本（产物用完删除） 与 tests/。任何跨用户读写成功、迁移数据丢失、身份冒用或幂等冲突导致多写，都阻断这一切片的后续扩展。调整接口/数据库时保留迁移链和合同测试；在 MyCareer Spike 后修订本 ADR，不能把暂未复用解释成永久弃用。
