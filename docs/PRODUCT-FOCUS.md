# CareerPilot 功能收敛与资料复用设计

更新：2026-10-28（Asia/Shanghai）。目标导航改为 AI 助手及学习与求职；旧五入口设计作为业务归属和历史参考。现有 React、LangGraph、私人草稿及结构化经历继续复用同一来源和事实链，保留 Docker。实际开发范围见 PLAN 与 [实现契约](WEB-CONTRACTS.md)。

## 1. 当前产品决策

CareerPilot 聚焦本人本地使用的成长求职助手：围绕目标岗位，把能力差距变成可执行的学习与项目，再把真实成果用于简历、申请和面试，反馈回下一轮成长。

主链为：`个人资料 → 目标与 JD → 能力差距 → 学习/项目 → 成果证据 → 简历/申请/面试 → 复盘与重排`。

功能进入主流程须能说明：服务哪个环节、复用哪些已有事实、产生什么可追踪结果。没有明确用途的扩展不因旧任务已验收而自动迁入网页端新栈。

当前范围以本文和 PRD §0.4 为准；旧 V0–V4、CP 任务及 110 条功能需求保留历史追踪，不能作为新栈全部必做承诺。技术栈按 [网页端重构规范](WEB-REFACTOR-PLAN.md) 与 [ADR-029](ADR-029-web-stack-docker.md) 完整替换，保留 Docker Compose，产品范围按本文收敛执行。原桌面草案已失效，当前运行版本为原位替换的新网页栈。

## 2. 已发现的问题及依据

| 优先级 | 发现 | 已核对的实现 | 处理决定 |
| --- | --- | --- | --- |
| 高 | 职业决策有两个平行入口 | `static/index.html` 同列 explore、directions；`directions.py` 保存方向视图，`growth.py` 另有目标预览/接受 | 方向比较归入目标与岗位；保留单一主目标及变更预览，不再要求重填一份画像 |
| 高 | 材料导入入口割裂，使用者易重复上传 | `static/growth.js` 提供材料→记忆；`static/hiring.js` 提供简历导入→事实；`resumes.import_preview` 实际已复用 `growth.import_material` | 统一资料入口与已导入材料选择，继续复用底层解析；不再新增解析器或事实仓库 |
| 高 | 成果到求职材料的状态难理解 | `project_workflow.py` 有 STAR 草稿、本人确认及简历事实转换；`resumes.py` 另有事实有效性与版本 | 保留项目证据/事实/简历快照的职责区别，用连续流程引导，不能用删除确认来消除重复 |
| 高 | 把历史平台蓝图当成当前必做范围 | PRD 原 §15 声明“不缩减最终范围”；桌面计划 R2 原要求迁移全部已实现入口 | 当前聚焦范围覆盖旧默认；逐项迁移保留/合并能力，延期项保留历史和个人数据的读取、导出、删除路径 |
| 中 | 学习、资料、复盘与提醒缺少一个执行入口 | index 中 learning、sources、progress、local-tools、directions 并列；`progress.js`、`personal_tools.py` 分别提供周期报表和季度复盘 | 学习执行合并，统一时间范围的复盘入口；通知统一偏好和收件箱，日历按需导出 |
| 中 | 不符合本人使用的扩展增加日常负担 | `collaboration.py`、`application_lab.py`、`agent_experiments.py` 及运营相关模块 | 协作、申请模拟、专家实验退出日常流程；本地维护仅保留必要诊断和治理 |
| 中 | 档案首次填写要求过多 | `ProfileInput` 要求专业、年级、毕业日期、城市、周分钟；`profileForm` 一次展示全部 | 分步引导、按动作补充缺项；未完成的档案先存草稿，规划/匹配前校验必需条件，不填虚构日期或零薪资 |

这是维护与流程审查，尚未进行使用者任务计时或真实效果评测；“入口多”和“需跨页操作”来自源码，不据此声称已测得效率提升。

## 3. 目标导航与旧入口归属

2026-10-28 新目标为两个日常主入口：AI 助手和学习与求职（学习、求职页内标签）。目标岗位、我的资料与设置作为辅助入口；旧路由继续可达。下表记录业务归属，不再表示五项常驻主导航；实际实现与验证状态见 PLAN。

| 目标入口 | 负责的事情 | 当前入口归属 |
| --- | --- | --- |
| 今日行动 | 当前目标、1–3 项优先行动、到期事项、助手、复盘摘要 | dashboard；progress 的通知和摘要 |
| 目标与岗位 | 选方向、主/备选目标、导入 JD、收藏/对比、差距与匹配 | explore、market、directions 的目标与比较、skills 的诊断视图 |
| 学习与实践 | 周计划、资源、测验、错题、项目执行、学习复盘 | learning、sources 的学习资源、portfolio 的项目执行、directions 的练习、progress 的报表 |
| 求职 | 简历版本与导出、申请看板、文字面试与复盘、按需 Offer 对比 | recruiting；local-tools 的 Offer；portfolio 的成果使用入口 |
| 我的资料 | 基础档案、材料、经历、项目成果、已确认事实、来源和历史 | settings 的档案/材料/时间线；portfolio 的成果管理；sources 的本人导入材料 |
| 设置（辅助） | 本地数据位置、模型/授权、通知、备份、导出/删除、运行诊断 | 原 settings 与 operations 中必要的本人维护能力 |

能力地图作为目标详情内可展开视图保留，作品集作为“我的资料→项目成果”保留；这里合并的是入口和编辑职责，不删除证据、图谱、项目或历史。学习与实践只链接同一个项目记录，求职只选择成果事实，不复制项目表单。

旧 collaboration、local-tools 中延期的实验页不迁为常驻主入口。旧深链接迁移时提供新位置或历史说明，不能静默落入空页面。诊断与开发测试控件不放在日常主导航。

## 5. 资料填写与复用规则

W-074 补充管理要求：当前档案、材料、经历/文字补充、练习项目、求职事实、来源、JD、简历/申请/材料草稿、计划、学习日志及反思在“我的资料→全部资料”统一检索和管理，原分区同步提供管理操作；沿用原表单及领域服务。原文修改需重新确认，事实变更提示旧简历重新核对；删除前列出所属子项及阻塞依赖，不自动删除其他独立业务资料。考核结论及历史简历采用重测/撤回或新增版本，不能任意改写评分与既有快照。

W-077 补充：学习计划及任务可直接编辑、增删和预览确认；已完成、进行中、锁定及其必要先修任务保持保护。全部资料扩展至 21 类，纳入职业目标、面试/复盘、译文、Offer、匹配快照、调整预览及复习安排；这些新增业务记录以明确的移入历史/恢复管理。匹配和考核结论仍由原业务生成，支持修改说明而不手改评分；不自动取消后台任务、脱钩学习日志或删除目标历史。

目标为“同一事实填写一次，使用时选择；新用途确认一次，修改时显示影响”。本人确认是陈述授权，客观技能验证是另一维度，两者不能合成一个真假开关。

### 5.1 共享资料与派生输出

| 资料 | 唯一编辑位置 | 被哪些流程引用 | 修改后的行为 |
| --- | --- | --- | --- |
| 档案与求职约束 | 我的资料→基础档案 | 目标、匹配、规划、简历教育信息 | 展示受影响范围，确认后更新当前引用；不改旧简历/申请快照 |
| 原始材料及摘录 | 我的资料→材料 | 经历/项目、已确认事实、学习来源 | 原文保留来源/版本；修订生成新版本，不把同文不同来源直接合成同一证明 |
| 教育/实习/工作/项目经历 | 我的资料→经历/项目成果 | 简历、项目面试、自我介绍、复盘 | 同一个条目按用途选字段，不能各处维护平行事实 |
| 技能与证据 | 目标详情→能力，编辑链接至原证据 | 缺口、计划、匹配、简历 | 展示证据范围/版本/有效性；完成学习不自动 verified |
| 简历事实 | 我的资料→可用于求职的事实 | 简历与材料生成 | 引用已确认来源；撤回/失效后禁止新用并提示旧输出风险 |
| 简历版本与申请 | 求职 | 导出、申请、面试上下文 | 固定版本快照，不能因上游修改而悄悄改写已提交内容 |

现有基础：`growth` 已有 material/memory/profile，`resumes` 已可引用 profile/memory，项目可转换事实。缺口是统一选择、去重、结构化经历编辑和草稿恢复；不能把上述已有复用重新开发一遍。优先扩展这些领域记录和适配层，R0 再确定具体 Schema，不在所有页面加入新 `profile_v2`/`facts_v2`。

### 5.2 填写流程

1. 首次仅选择“准备方向/学习提升/正在求职”，导入一份已有材料或手动建档；允许稍后补充，不根据文本默认宣布能力已掌握。
2. 先保存私人草稿，再按用途提示缺项：生成计划要有明确周预算；匹配需要对应岗位硬约束；导出简历要求选定已确认事实。正式档案保持完整校验；分步草稿已通过独立 drafts 契约实现，不直接放宽正式档案校验。
3. 导入时展示已有同内容/相似条目及来源；优先复用记录或建立来源关联。完全重复确认请求须幂等；语义相似仅建议合并，不能自动覆盖。
4. 把栏目、时间、角色、个人行动、结果与来源分开填；日期未知可写年月或未知并记录精度，不能伪造某月一日。多段教育/经历独立记录，不塞进一块“偏好”文本。
5. 从已保存资料预填；用户选择使用范围后生成草稿。缺失结果/指标显示待补充，模型不能补造收益、团队人数、排名或贡献率。
6. 逐字段确认提取/生成内容；历史事实无变化时可直接选择复用，发生版本变化、用途授权变化或失效时再确认。危险外部动作仍单独确认。
7. 切页/重启后可恢复私人草稿，显示保存状态及失败重试；版本冲突保留本人输入并比较差异，不能以“恢复”自动提交。

草稿默认保存在本人本地业务存储，绑定用户和资料类型；不把敏感正文长期放浏览器 localStorage，不存访问令牌/模型密钥。草稿纳入账号导出、删除与撤销治理，保存草稿不代表允许外部模型处理；退出或切换身份后不能显示上一人的草稿。

### 5.3 字段与辅助交互

- 每个字段标明用途和格式，帮助文字仅在需要时显示；原文/确认/撤销提示保留，遵循 W-049 的单一标题与精简层级。
- 周预算输入用小时/分钟，内部统一分钟；城市用可增删选项，薪资允许“未确定”，时区给默认建议并允许有效 IANA 标识。
- 原文提取字段显示摘录；自填与模型建议分开，支持“保留原文/采用建议/自行修改”。
- 完整度按当前动作展示“缺少周预算/项目行动”等可处理缺项，不做全局资料评分，不鼓励填写无关或敏感信息。
- 提供填写提示和可复制结构，见 [资料填写指南](PROFILE-WRITING-GUIDE.md)；指南不代表已增加 PDF/Word 原件导入功能。
