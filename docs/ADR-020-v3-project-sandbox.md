# ADR-020：独立代码评测与真实项目回执

日期：2026-10-21。状态：V3 首批实现；完整阶段仍开发中。

## 决定

1. 先提供一个有版本的 Python 数据汇总练习，依据本人岗位中的 Python 要求推荐，披露先修、180 分钟拆分及本人周预算的独立估算。估算不会自动占用现有学习计划。项目、代码提交、回执、确认事实均复用私有 GrowthRecord/Revision，沿用所有权、事务锁、乐观版本、创建幂等与账号导出/删除，无新增数据库迁移。
2. HTTP 仅支持创建、提交、查询、撤回和确认事实，没有上传评测结果的接口。应用和 Worker 不获得 Docker socket。可信操作者在宿主机运行 `scripts/project_sandbox.py`，经 Compose exec 领取业务库中的排队提交、运行隔离容器并提交结果。后台业务 Worker 本身不执行代码；尚未安装自动轮询服务，排队结果不会伪报成功。
3. 评测镜像不包含应用代码、账号数据或凭据，基础镜像固定 digest；每次执行固定到本地不可变 image ID。独立容器采用无网络、非 root、只读根文件系统、无宿主挂载、移除 capabilities、no-new-privileges、CPU/内存/进程/文件配额及 16 MiB 临时目录。宿主按真实时间限制执行；只保留最多 16 KiB stdout，超限后继续丢弃读取以免阻塞 Docker 清理，随后移除容器。不保存任意 stdout/stderr 到业务库。
4. 可信宿主比较五项测试的输出；期望结果不会进入代码容器，用户代码不能直接提供可信通过标志。回执保存源文件 SHA-256、制品版本、测试版本、evaluator/rubric 版本、image ID 和逐项结果。有限测试仅支持该练习的 Python 数据处理行为，不证明原创性、真实业务指标或完整岗位胜任。
5. 评测租约为 120 秒，重领会更换令牌；业务库只存令牌摘要，原令牌仅经操作者通道传递。过期/旧令牌无法提交。最多三次领取，超限留系统异常；每人最多三项排队/运行中提交。撤回或被新提交替代的运行结果不能写证据。完成后重复提交结果拒绝，不重复写台账。恢复采用重新隔离执行，不复用上次容器。
6. `passed` 和 `user_failed` 分别写 project 范围的通过/失败证据；`system_error`、`timeout`、`manual_review` 不写能力结论。项目证据不会写入 foundation 快照。V2 消费适配器继续检查当前证据、有效期、撤销、回执和制品的版本/指纹；最新失败阻止旧通过复活，基础设施故障保留已有有效证据。
7. 通过后可以预览固定、保守的成果陈述，未知贡献、性能与业务收益保持待确认。本人确认才新增简历事实；事实保存制品与回执版本。事实关联从当前确认记录派生，不修改已评分回执。撤回、过期、证据撤销或来源失效会阻止后续材料使用；旧简历版本仍保留历史文本。已有关联事实可供 V2 文字面试读取，面试分数仍不写能力台账。

## 分阶段依赖

CP-162 的前置 CP-191 与 V2 完整项目分项存在阶段出口依赖。本批实现 CP-161/180 的生产链及 CP-181 的事实链接，再增量接入 CP-162 的项目回执部分，之后重审 CP-190/191；不将任务包之间的出口条件误作禁止实现其依赖的循环。原任务定义与最终验收标准不变。

## 边界与后续

本地单用户 Docker 约束与恶意样例演练不等于生产逃逸审计。公网多用户发布需专用执行节点、更强隔离和并发/配额/供应链审核。静态扫描只检查纯文本、大小、控制字符与明显凭据/EICAR；不声称完整杀毒。暂不运行第三方依赖、GitHub 克隆/私有仓库或任意工程构建。CP-113、143、154 尚未实现；CP-180 的自动排程/里程碑编辑和更丰富成果文件、CP-181 的自由 STAR 草稿与 CP-162 的完整验收仍待后续。七项 V3 任务不得整体提前验收。
