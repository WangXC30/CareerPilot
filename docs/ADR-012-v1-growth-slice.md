# ADR-012：V1 首批档案、材料、目标与 JD

- 日期：2026-10-20，Asia/Shanghai。
- 状态：首批本地实现并验证；不代表 V1 出口通过。
- 决策依据：用户明确要求开始 V1；沿用 B3→B4→B5 顺序。

## 选择与边界

继续使用现有 FastAPI、SQLite/SQLAlchemy、Alembic、原生静态页面和 Compose。
本轮不引入另一套前端或外部解析服务。先打通档案、材料确认、目标切换和手动 JD 导入，
将领域用例放在 `growth.py`，HTTP 适配放在 `growth_api.py`，供后续 Agent 共用规则。

档案、材料、记忆、JD 和目标预览使用 `growth_records` 保存当前聚合，
`growth_revisions` 保存每次更新的快照。Pydantic 为每种输入定义独立契约，禁止客户端传入
所有权、验证状态和内部版本。SQL 条件更新检查版本，旧版本返回 412；历史恢复创建新版本。
两个表均使用用户/租户复合外键，历史表同时约束父聚合所有权。当前 JSON 载荷由服务控制，
复杂组合检索和技能/计划领域进入下一批后应建立独立索引与类型化表，不能据此宣称搜索性能达标。

原始文本和来源只保存在私有数据库，不暴露静态文件路径。本轮接受 UTF-8 txt/md/json，
单文件上限 1MiB，使用现有凭据扫描、来源审查和限额。解析器保守地按行提供候选陈述，
用户勾选、纠错和确认后才写入记忆。`document_fact` 表示材料中的陈述，不能证明技能。
所有此类记忆的技能状态保持 `unverified`；客观能力证明由 CP-141/160 后续负责。
单条记忆删除会移除其内容与修改历史，保留无正文审计；原材料保留，整账户删除仍属 CP-101。

JD 使用可复现的标签/技能规则，不伪装成真实模型抽取。字段保留原文 Unicode 码点范围、引用、
抽取器版本；歧义或无法识别时返回 unknown。要求/优先/提及按局部语句区分。
来源链接仅作引用保存，本轮不发起任何网络抓取。原文完全相同时合并来源；
同一 URL 更新原文时建立新版本；近重复只提示人工核查。导入持有同一用户记录的事务行锁，
避免并发导入生成两份相同记录；同时沿用来源按分钟限额。

目标预览保存完整目标集合的摘要、当前主目标及目标名称。接受时重新检查摘要，
用条件写入消费预览，再按版本切换目标，数据库仍强制主目标唯一。取消不修改主目标。
本轮尚无真实学习计划和匹配结果，影响说明明确要求后续重评，不生成虚构计划。

## 备选、取舍与验证

暂不采用自动推断事实、直接 URL 抓取或生成未经客观考核的 verified 技能。
当前抽取召回率有限、搜索字段尚不完整；这使本轮可以在现有来源/同意范围内验证真实持久化链，
但不满足 CP-101/120/130/131/132/170 的完整验收。正式登录、账户导出删除、PDF/Word、
职业百科、完整检索、来源生命周期、模型金标及网络工具继续按原任务交付。

验证见 历史验证摘要（产物已清理）：后端回归、Chromium 业务操作与截图、
SQLite 迁移往返、PostgreSQL 结构合同、开发卷备份和升级。

## 回滚

升级前停止 API/Worker 并建立 `backups/pre-v1-0003-20261020.db` 一致快照。
0003 增量迁移不修改原 V0 表。降级会删除本轮两个新表，必须先备份 V1 数据；
不要在已有 V1 用户数据的开发卷上直接执行 downgrade。恢复旧库时需搭配匹配旧迁移的源码。
